# Skipped test rows this repository accepts, and where.
#
# One rule per line: PLATFORMS, package, test. Platforms is a
# comma-separated list of the operating systems this repository builds
# for, or an asterisk for all of them. tools/skipcheck reads this file
# on every run and keeps no copy of its own, so deleting a line here
# measurably changes what the suite allows — which is how anyone can
# check it is really being read.
#
# THE RULE THIS FILE EXISTS FOR: a skipped row prints nothing in a
# non-verbose run, so a green tick over a row that stopped running looks
# exactly like a green tick over one that passed. Several rows here skip
# on conditions that are honest on one platform and a broken environment
# on another — a missing program, a filesystem feature the account cannot
# use, a permission the runner does not hold. A skip that is not listed
# below fails the run.
#
# WHAT DOES NOT BELONG HERE is as important as what does, and the test is
# whether the skip could ever be LEGITIMATE — not whether it happens to
# occur on the machine in front of you. The differential row that compares
# this project's ignore-rule matcher against the real program skips when
# that program is not installed; the machine running these tests obtained
# the source with it, so that skip can only mean something is wrong. It is
# deliberately absent from this file, and that absence is what makes the
# skip impossible to hide.
#
# A line here is a claim that the skip is legitimate on the platforms it
# names. Say why in a comment above it; the next reader is deciding
# whether the claim still holds.
#
# WHAT THIS GATE CANNOT SEE, stated here rather than only in a review,
# because here is where its reader is. It works by reading the skip
# EVENTS a test run reports, so it sees a row that ran and gave up. It
# cannot see a row that never ran at all:
#
#   - a row excluded by a build tag is not compiled into the binary, so
#     nothing reports it;
#   - a row behind a TestMain that returns without calling m.Run()
#     likewise reports nothing.
#
# In both cases the run is green and the file below is silent, which
# looks exactly like a row that passed. It is the same sentence the walk
# reached from the other side: a row that does not exist cannot report
# that it did not run.
#
# The consequence for whoever writes the next platform-dependent row: a
# BUILD TAG is the right tool when the row cannot compile on a platform,
# and it buys the compiler's own check that the file still builds on the
# legs it does target — but it moves the row outside this gate's view, so
# say in the file itself which platform it belongs to and why. A runtime
# skip stays visible here and is the right tool when the row compiles
# everywhere and only the environment decides.

# The child half of a row that re-executes the test binary to watch it
# die of a signal. It is a test only when the parent invokes it with the
# marker in the environment; on an ordinary run it has nothing to do.
* github.com/curiouspub/cli/internal/ui TestInterruptHelperProcess

# The rows needing a real symbolic link. MEASURED: the machine this suite
# runs on can create them, so these do not skip there today — and they
# are declared anyway, because an account without the privilege is an
# environment this project supports and the skip would be honest in it.
#
# THAT IS THE LINE THIS FILE DRAWS, and the first draft drew it in the
# wrong place: it left these out on the grounds that they do not skip
# here, so that anybody would be "told" if that changed. Being told would
# mean a red build on a correctly-configured machine, which is how a gate
# earns its reputation for crying wolf and then gets switched off. The
# question is not whether a skip HAPPENS here — the report at the end of
# every run answers that, and answers it better. The question is whether
# the skip would be LEGITIMATE, and only a skip that could never be
# legitimate belongs outside this file.

# The row that asks the release tool to validate the release
# configuration. That tool is not a build dependency of this module and
# is not installed by `go` — a contributor who has never cut a release
# has no reason to have it, and the skip is honest on their machine.
#
# WHAT THE SKIP COSTS, because a line here is a claim and not a note.
# This is the only row that asks the tool itself whether the
# configuration is still one it accepts: a renamed key, a deprecated
# block, a schema that moved under a version bump. Every other property
# of that file — what it builds, for which platforms, with which flags,
# signed how, published where — is asserted by rows that need no tool and
# run on all three platforms. And the workflow that builds a snapshot on
# every change installs the tool at an exact pinned version and runs the
# same configuration through a real build, so what the skip loses is
# local signal rather than the check.
#
# It is a RUNTIME skip and not a build tag on purpose. A tagged row never
# enters the test binary, so nothing reports it and this gate cannot see
# it at all — which looks exactly like a row that passed.
* github.com/curiouspub/cli/internal/guard TestReleaseConfigIsAcceptedByTheReleaseTool

# A directory the walk cannot read has to be built by taking away the
# read bit, and two environments legitimately refuse to produce it:
# Windows, where permission bits do not gate a directory read the same
# way, and any account whose process ignores them — root in a container
# being the ordinary case. The row checks that the fixture really is
# unreadable before trusting it, so the skip means the environment said
# no rather than the row guessing.
* github.com/curiouspub/cli/internal/pack TestWalkRefusesANestedDirectoryItCannotRead
